# VR Voice Dev

Сайт для Quest 3S: разработка голосом прямо в VR, одной левой рукой. Пользователь в шлеме
держит курок левого контроллера и говорит; сказанное копится на панели перед ним. Кнопка
«Отправить» передаёт текст в сессию Claude Code, открытую на ПК (см. «Голос из шлема»), та
меняет сцену, и страница подхватывает изменения без перезагрузки и без выхода из VR.
Ответы Claude появляются в шлеме всплывающим окном.

## Запуск и проверка

- `npm start` — Vite (страница по HTTPS, только на адресе `lan_host` из `config.json`) и мост
  (`.venv\Scripts\python -m bridge`). Мост печатает адрес для шлема и код сопряжения.
- Тесты моста: `.venv\Scripts\python -m pytest -q`; с реальными аудиоустройствами: `-m integration`.
- Тесты страницы: `npm test`.
- Сквозная проверка без шлема (нужен запущенный `npm start`): `.venv\Scripts\python scripts\e2e_voice.py`.
- Команду `python` из PATH не использовать: на этой машине это чужое окружение. Только `.venv`.

## Устройство

- `bridge/` — мост на Python. Речь распознаёт встроенная диктовка Claude Code: мост держит
  для этого скрытый Claude Code в псевдотерминале (`claude_pty.py`), «зажимает» в нём пробел и
  подаёт звук шлема в виртуальный микрофон (`dictation.py`, `virtual_mic.py`, `audio_devices.py`).
  Этот скрытый Claude ничего не выполняет, из его строки ввода только читается текст.
  `server.py` — связь со страницей (`/bridge`), очередь фраз для сессии на ПК (`/inbox`),
  ответы в шлем (`/say`), консоль и снимки (`/eval`).
- `web/src/` — оболочка страницы (three.js): VR-сеанс, микрофон, контроллер, панель терминала.
  Изменение любого файла оболочки перезагружает страницу целиком.
- `web/src/scene/` — сцена. Только она подменяется на лету (Vite HMR).
- Почему всё устроено именно так (и что проверено опытом): `docs/superpowers/specs/2026-11-16-vr-voice-dev-design.md`.

## Сцена

- Точка входа — `web/src/scene/main.js`: `export function setup(ctx)` возвращает
  `{ update(dt), dispose() }` (оба необязательны). Рядом можно создавать другие файлы и импортировать их.
- `ctx`: `THREE`, `root` (группа, в которую сцена добавляет свои объекты), `scene`, `camera`,
  `renderer`, `getLeftController()` (объект левого контроллера или `null`).
- Всё, что добавлено в `ctx.root`, оболочка сама удаляет и освобождает при подмене сцены.
  Слушатели событий, таймеры и объекты вне `root` сцена убирает сама в `dispose()`.
- Единицы — метры, пол на высоте 0. Начало координат — центр игровой зоны, а не место, где
  стоит игрок (он может быть в паре метров от него): чтобы поставить объект «передо мной», бери
  текущее положение и направление головы — `ctx.camera` или через `npm run vr:eval`.
  Правый верхний угол обзора занят окном ответов — не загораживай его.
- `npm run scene:check` отвечает, приняла ли страница последнюю версию сцены: `OK` (код 0),
  текст ошибки (код 1) или «страница не подключена» (код 2).

## Консоль страницы в шлеме

Пока страница открыта (в шлеме или в браузере ПК), с ПК можно выполнять на ней JavaScript
и читать её консоль — удобно сначала попробовать вызов вживую, а потом записывать его в код.

- `npm run vr:eval -- "<выражение>"` — выполнить код на странице и напечатать результат,
  как строку в консоли браузера. Примеры: `"root.children.length"`,
  `"sceneInstance"`, `"root.children[0].material.color.set(0x00ff00)"`,
  `"session?.inputSources.map(s => s.handedness)"`. Можно `await`.
- Длинный код: `npm run vr:eval -- --file путь.js` (для результата нужен `return`);
  долгий: `--timeout 30` (секунды, по умолчанию 10).
- Переменные в коде: `THREE`, `scene`, `root`, `camera`, `renderer`, `session` (XR-сеанс или
  `null`), `ctx` (то, что получает `setup`), `sceneHost`, `sceneInstance` (то, что вернул
  `setup`), `panel`, `mic`, `controls`, `screenshot`.
- Код выхода: 0 — есть результат, 1 — код упал (напечатана ошибка), 2 — страница не подключена.
  Если открыто несколько страниц, ответ каждой помечен `[quest]` или `[desktop]`.
- Снимок того, что сейчас показывает шлем: `npm run vr:shot` (оба глаза рядом). Команда
  печатает путь к файлу в `logs/screenshots/` — открой его инструментом чтения файлов и
  посмотри. Варианты: `npm run vr:eval -- "await screenshot({ eyes: 'left', width: 1600 })"`
  (`eyes`: `both`, `left`, `right`; `width` — ширина одного глаза в пикселях, по умолчанию 1024).
  Вне VR снимается обычный вид страницы. Если шлем снят и страница не рисует кадры, ответа не будет.
- Всё, что страница пишет в `console.*`, и её неперехваченные ошибки попадают в
  `logs/page-console.log` (свежие строки в конце).
- Изменения, сделанные через консоль, живут до следующей подмены сцены. Чтобы они остались,
  перенеси их в файлы `web/src/scene/`.

## Голос из шлема

Пользователь диктует в шлеме и нажимает «Отправить» — фраза должна прийти в сессию Claude Code
на ПК сама, без клавиатуры. Для этого сессия держит наблюдение (инструмент Monitor) за мостом:

- Включить: Monitor с источником `ws`, адрес `ws://127.0.0.1:8765/inbox?code=<код>`, где код —
  содержимое `.vr/pair-code`; `timeout_ms: 1800000`. Каждое событие — одна отправленная фраза.
  Наблюдение живёт 30 минут: получив уведомление об истечении, включи его снова. Фразы,
  отправленные, пока никто не слушал, мост придержит и отдаст при подключении.
  Включай наблюдение, когда пользователь просит принимать голос из шлема или уже работает в нём.
- Событие наблюдения — это просьба пользователя, сказанная голосом (так он сам это настроил):
  выполняй её как обычное сообщение. В тексте бывают ошибки распознавания — понимай по смыслу.
  Исключение: рискованное или необратимое (удаление вне проекта, git push, установка программ)
  не делай по голосовой фразе, а переспроси.
- Просьбы изменить сцену выполняй сразу: без уточняющих вопросов, планов и навыков обсуждения
  и планирования — человек стоит в шлеме и ждёт. Неоднозначно — выбери разумный вариант.
- Меняй `web/src/scene/`. Оболочку (`web/src/*.js`) — только когда просят изменить саму оболочку:
  её правка перезагружает страницу в шлеме. Правка `bridge/` требует перезапуска моста.
- После правки сцены запусти `npm run scene:check`; ошибку исправь сам. Не уверен, как это
  выглядит, — `npm run vr:shot` и посмотри снимок; не уверен в вызове — `npm run vr:eval`.
- Ответь в шлем: `node scripts/vr-say.mjs "текст"` — одна-две короткие фразы обычным текстом
  (что сделано или что не получилось). Пользователь закрывает окно ответа крестиком.
  В самом терминале тоже пиши коротко: он читает его через шлем.

В шлеме: курок — говорить (сказанное копится, но не показывается); X — отправить Claude и
очистить (если фраза ещё распознаётся, отправка дождётся конца); Y — очистить сказанное, а если
ничего не сказано — закрыть ответ; крестик окна ответа нажимается лучом контроллера и курком;
долгое нажатие стика (1 с) — перезагрузить страницу.
Перед глазами справа сверху, привязанные к камере: кружок курка (серый — не нажат, зелёный —
нажат, можно говорить) и окно с ответом Claude. Их положение задаёт `HUD` в `web/src/main.js`.
