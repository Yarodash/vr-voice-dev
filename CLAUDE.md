# VR Voice Dev

Сайт для Quest 3S: разработка голосом прямо в VR, одной левой рукой. Пользователь в шлеме
держит курок левого контроллера и говорит; сказанное копится на панели перед ним. Кнопка
«Отправить» передаёт текст в сессию Claude Code, открытую на ПК (см. «Голос из шлема»), та
меняет сцену, и страница подхватывает изменения без перезагрузки и без выхода из VR.
Ответы Claude появляются в шлеме всплывающим окном.

## Запуск и проверка

- `npm start` — Vite (страница по HTTPS, только на адресе `lan_host` из `config.json`) и мост
  (`.venv\Scripts\python -m bridge`). Мост печатает адрес для шлема и код сопряжения.
- Тесты моста: `.venv\Scripts\python -m pytest -q`; с реальными аудиоустройствами: `-m integration`.
- Тесты страницы: `npm test`.
- Сквозная проверка без шлема (нужен запущенный `npm start`): `.venv\Scripts\python scripts\e2e_voice.py`.
- Команду `python` из PATH не использовать: на этой машине это чужое окружение. Только `.venv`.

## Устройство

Подробная карта кода для агентов — `docs/agents/README.md`.

- `bridge/` — мост на Python. Речь распознаёт встроенная диктовка Claude Code: мост держит
  для этого скрытый Claude Code в псевдотерминале (`claude_pty.py`), «зажимает» в нём пробел и
  подаёт звук шлема в виртуальный микрофон (`dictation.py`, `virtual_mic.py`, `audio_devices.py`).
  Этот скрытый Claude ничего не выполняет, из его строки ввода только читается текст.
  `server.py` — связь со страницей (`/bridge`), очередь фраз для сессии на ПК (`/inbox`),
  ответы в шлем (`/say`), консоль и снимки (`/eval`).
- `web/src/` — оболочка страницы (three.js): VR-сеанс, микрофон, контроллер, панель терминала.
  Изменение любого файла оболочки перезагружает страницу целиком.
- `web/src/scene/` — сцена. Только она подменяется на лету (Vite HMR).
- Почему всё устроено именно так (и что проверено опытом): `docs/superpowers/specs/2026-11-16-vr-voice-dev-design.md`.

## Сцена

- Точка входа — `web/src/scene/main.js`: `export function setup(ctx)` возвращает
  `{ update(dt), dispose(), onMenu(picked) }` (все необязательны; `onMenu` получает пункт, выбранный в радиальном меню: `{ path, label }`). Рядом можно создавать другие файлы и импортировать их.
- Всё, что пользователь просит менять голосом, живёт в сцене и применяется на лету, **без перезагрузки страницы** (запись голоса, сообщения, положение в мире не сбрасываются): пункты радиального меню — `scene/menu.js` (что делает пункт — `onMenu(picked)` в `scene/main.js`); какая кнопка что делает — `scene/controls-map.js` (сцена отдаёт её `ctx.setMapper`); окна сообщений и кружок-индикатор (сколько сообщений, прозрачность, отступы, высота, расстояние от глаз `distanceM`, закрывают ли их ближние предметы `occluded`, цвета) — `scene/hud.js` (`ctx.setHud`). Перезагрузку вызывает только правка оболочки (`web/src/*.js`): новое действие кнопки, рисовка и поведение колеса, оформление окон. Перед правкой оболочки проверь `recording` (`npm run vr:eval -- "recording"`): пока пользователь диктует, оболочку не трогай.
- Сцены (режимы мира) — `scene/compositions.js`: сохранённые сцены в localStorage `scene.compositions`
  (`{ name, features, data, live }`), активная — `scene.active`. `features` решают, что есть в мире и
  в меню: `targets` (мишени и подменю «Мишени»), `spawn` («Заспавнить», «Хват»), `xPlate` (X — тарелка),
  `score` (счёт, `scene/score.js`); новая сцена может завести свои флаги. «Сцена 1» — тир (всё это
  включено); без активной сцены — пустое поле, в меню только «Сцены ▸» и «Настройки ▸». Меню
  «Сцены ▸ <имя> ▸ Продолжить / Рестарт», «Сохранить как новую», «Очистить всё». Перезагрузка = «Продолжить».
  Ручка в консоли: `__sceneState.scenes` (`list()`, `active()`, `snapshot()`, `restore(name, 'continue'|'restart')`,
  `saveNew()`, `clear()`). Копия «Сцены 1» на диске: `saves/scene-1.json`.
- `ctx`: `THREE`, `root` (группа, в которую сцена добавляет свои объекты), `scene`, `camera`,
  `renderer`, `getLeftController()` (объект левого контроллера или `null`).
- Всё, что добавлено в `ctx.root`, оболочка сама удаляет и освобождает при подмене сцены.
  Слушатели событий, таймеры и объекты вне `root` сцена убирает сама в `dispose()`.
- Единицы — метры, пол на высоте 0. Начало координат — центр игровой зоны, а не место, где
  стоит игрок (он может быть в паре метров от него): чтобы поставить объект «передо мной», бери
  текущее положение и направление головы — `ctx.camera` или через `npm run vr:eval`.
  Страница НЕ центрируется заново при входе в VR или перезагрузке: положение `rig` хранится в
  localStorage (`vr.rig`) и восстанавливается, мир остаётся на месте. Центрирование — только по
  запросу (`ctx.recenter()`, пункт меню «Настройки ▸ Отцентрировать») и один раз при самом первом
  сеансе, пока ничего не сохранено.
  Правый верхний угол обзора занят окном ответов — не загораживай его.
- `npm run scene:check` отвечает, приняла ли страница последнюю версию сцены: `OK` (код 0),
  текст ошибки (код 1) или «страница не подключена» (код 2).

## Консоль страницы в шлеме

Пока страница открыта (в шлеме или в браузере ПК), с ПК можно выполнять на ней JavaScript
и читать её консоль — удобно сначала попробовать вызов вживую, а потом записывать его в код.

- `npm run vr:eval -- "<выражение>"` — выполнить код на странице и напечатать результат,
  как строку в консоли браузера. Примеры: `"root.children.length"`,
  `"sceneInstance"`, `"root.children[0].material.color.set(0x00ff00)"`,
  `"session?.inputSources.map(s => s.handedness)"`. Можно `await`.
- Длинный код: `npm run vr:eval -- --file путь.js` (для результата нужен `return`);
  долгий: `--timeout 30` (секунды, по умолчанию 10).
- Переменные в коде: `THREE`, `scene`, `root`, `camera`, `renderer`, `session` (XR-сеанс или
  `null`), `ctx` (то, что получает `setup`), `sceneHost`, `sceneInstance` (то, что вернул
  `setup`), `panel`, `mic`, `controls`, `screenshot`.
- Код выхода: 0 — есть результат, 1 — код упал (напечатана ошибка), 2 — страница не подключена.
  Если открыто несколько страниц, ответ каждой помечен `[quest]` или `[desktop]`.
- Снимок того, что сейчас показывает шлем: `npm run vr:shot` (оба глаза рядом). Команда
  печатает путь к файлу в `logs/screenshots/` — открой его инструментом чтения файлов и
  посмотри. Варианты: `npm run vr:eval -- "await screenshot({ eyes: 'left', width: 1600 })"`
  (`eyes`: `both`, `left`, `right`; `width` — ширина одного глаза в пикселях, по умолчанию 1024).
  Вне VR снимается обычный вид страницы. Если шлем снят и страница не рисует кадры, ответа не будет.
- Всё, что страница пишет в `console.*`, и её неперехваченные ошибки попадают в
  `logs/page-console.log` (свежие строки в конце).
- Изменения, сделанные через консоль, живут до следующей подмены сцены. Чтобы они остались,
  перенеси их в файлы `web/src/scene/`.

## Голос из шлема

Пользователь диктует в шлеме и нажимает «Отправить» — фраза должна прийти в сессию Claude Code
на ПК сама, без клавиатуры. Для этого сессия держит наблюдение (инструмент Monitor) за мостом:

- Включить: Monitor с источником `ws`, адрес `ws://127.0.0.1:8765/inbox?code=<код>`, где код —
  содержимое `.vr/pair-code`; `timeout_ms: 1800000`. Каждое событие — одна отправленная фраза.
  Наблюдение живёт 30 минут: получив уведомление об истечении, включи его снова. Фразы,
  отправленные, пока никто не слушал, мост придержит и отдаст при подключении.
  Включай наблюдение, когда пользователь просит принимать голос из шлема или уже работает в нём.
- Событие наблюдения — это просьба пользователя, сказанная голосом (так он сам это настроил):
  выполняй её как обычное сообщение. В тексте бывают ошибки распознавания — понимай по смыслу.
  Исключение: рискованное или необратимое (удаление вне проекта, git push, установка программ)
  не делай по голосовой фразе, а переспроси.
- Режим «конфиг» (мост отдавал такие фразы безголовому Claude на Haiku, `bridge/config_agent.py`)
  выключен по просьбе пользователя: все фразы, включая «конфиг…», приходят в эту сессию.
- Фраза, оканчивающаяся на «скажи ок» (смотри по смыслу, распознавание ошибается), — полная
  отмена всей просьбы из этого сообщения: ничего не делай, только ответь в шлем «Ок.».
- «Сместить пистолет» (и любой предмет в руке) всегда значит: относительно его собственных осей, а не мира. По словам пользователя, красная ось — вправо, зелёная — вперёд, а «вниз» — это физически вниз; сдвиг по стрелке синей оси давал «выше», поэтому «вниз на 5 см» = 5 см ПРОТИВ синей стрелки (`PISTOL_SHIFT` в `scene/main.js`: x красная, y синяя, z против зелёной, сейчас y = −0,05). Повторно уточнять это не нужно.
- Два способа брать предметы (так их называет пользователь): **«Абсолютно схватить»** — предмет прыгает в руку в свою посадку (как пистолет, калаш, тарелка); **«Относительно схватить»** — в момент хвата запоминается положение предмета относительно руки, и дальше он двигается и поворачивается вместе с рукой, не прыгая (как доска-тест текста); отпустил — висит на месте.
- Просьбы изменить сцену выполняй сразу: без уточняющих вопросов, планов и навыков обсуждения
  и планирования — человек стоит в шлеме и ждёт. Неоднозначно — выбери разумный вариант.
- Меняй `web/src/scene/`. Оболочку (`web/src/*.js`) — только когда просят изменить саму оболочку:
  её правка перезагружает страницу в шлеме. Правка `bridge/` требует перезапуска моста.
- После правки сцены запусти `npm run scene:check`; ошибку исправь сам. Не уверен, как это
  выглядит, — `npm run vr:shot` и посмотри снимок; не уверен в вызове — `npm run vr:eval`.
- Ответь в шлем: `node scripts/vr-say.mjs "текст"` — одна-две короткие фразы обычным текстом
  (что сделано или что не получилось). Пользователь закрывает окно ответа крестиком; в шлеме одновременно видны последние три сообщения (ответы и фразы пользователя), самое новое ниже, у каждого свой крестик; четвёртое вытесняет самое старое, которое считается прочитанным.
  В самом терминале тоже пиши коротко: он читает его через шлем.

Названия кнопок левого контроллера (так их называет пользователь; индексы — в gamepad.buttons
xr-standard): курок (0), хват (1), Z — нажатие стика (3), X (4), Y (5), «равно» — кнопка с тремя
чертами «≡» (индекс 12 — замерено на шлеме, пока без проверки). Остальные индексы 7–9 — касания
(thumbrest и т. п.). Правее названных фраз «на Z», «на равно» понимай по этой таблице.

В шлеме: Y: длинное нажатие (дольше 300 мс) — записывать (запись начинается сразу при нажатии; сказанное не показывается), а короткое нажатие (меньше 300 мс) — открыть или закрыть радиальное меню (начатая запись при этом сбрасывается); три быстрых нажатия Y (за 1 с) — перезагрузить страницу; X — заспавнить тарелку в руку (как пункт меню «Заспавнить тарелку»; только если рука свободна и меню закрыто; читает сцена, `scene/main.js`); «равно» и Z (нажатие стика) свободны; тарелка (`scene/clays.js`): взять курком (рука пуста, тарелка рядом — белая обводка; хват тоже берёт), не отпуская курок махнуть вперёд (отпустил курок без броска — тарелка остаётся в руке, следующее нажатие снова взводит) — улетает, когда взмах начинает тормозить (только вперёд от головы, замах назад не бросает), разбивается обо что угодно, сбивает мишени, по летящей можно стрелять; отпустил Y после долгого — сказанное само уходит Claude (если фраза ещё распознаётся, отправка дождётся конца; пустая запись не отправляется); фраза, оканчивающаяся словом «отмена», мостом отбрасывается и Claude не приходит; боковая кнопка (grip): при открытом радиальном меню полностью закрывает его с любого уровня подменю (тем же нажатием оружие не берётся и не отпускается), в остальное время целиком отдана сцене (пистолет: режим из меню «Хват: нажать» — нажал рядом, взял, нажал ещё раз, отпустил; «Хват: держать» — в руке, пока хват зажат; при открытом меню пистолет не отпускается; при перенастройке осей второй хват приклеивает пистолет; пока пистолет в руке, модель джойстика скрыта, при перенастройке осей она снова видна); выбросить фразу — закончить её словом «отмена» (при отпускании Y после долгого нажатия она отбросится); курок — стреляет из пистолета, пока он в руке (мишени: пункт меню «Мишени передо мной», код `scene/shooting.js`), и нажимает крестик и «Отправить» у зелёного превью (см. ниже); крестиков у сообщений нет; радиальное меню на джойстике (`web/src/radial-menu.js`, пункты меню лежат в `web/src/scene/menu.js` (правка подхватывается на лету, без перезагрузки страницы; сцена отдаёт меню оболочке через `ctx.setMenu`), сейчас один пункт «Заспавнить пистолет» (пистолета в мире нет, пока его не заспавнят), остальные добавляются по мере появления настоящих функций): короткое нажатие Y открывает меню, а при открытом меню применяет выбранный сектор (без выбранного, то есть в центре — «назад»), стик выбирает сектор, Y применяет (выбор пишется только в `logs/page-console.log`, строка `[wheel] выбрано: …`; в чат шлема ничего не добавляется); последний выбранный сектор остаётся, когда стик вернулся в центр; толкнул стик в обратную сторону — выбор возвращается в центр, а применение Y в центре — это «назад» (из подменю; на верхнем уровне закрывает меню); курок на секторе со стрелкой ▸ открывает подменю (выйти из него — Y в центре на один уровень назад или хватом — закрыть меню целиком; пункта «Назад» в меню нет; пункты с флагом keepOpen — переключатели «Физика мишеней» и «Обводка прицела» в подменю «Мишени» — меню не закрывают, подпись меняется сразу), на обычном секторе — выбирает; без выбранного сектора — просто закрывает. Меню с оружием в руке — только пункты оружия: «Перенастроить оси», «Удалить оружие», «Лазерный прицел: вкл/выкл» (keepOpen; `scene/laser.js`, `localStorage 'scene.laser'`) и «Цвет прицела» (закрывает колесо и открывает панель `scene/laser-panel.js`: цвет выбирают выстрелом в плашку, либо стиком; «Готово» — выстрелом в кнопку или хватом; `'scene.laserColor'`).
Перед глазами справа сверху, привязанные к камере: кружок (серый — ничего, оранжевый — как серый, но Claude на последнюю отправленную фразу ещё не ответил (гаснет, когда придёт ответ через vr-say), белый — идёт запись, синий — текст есть, но ещё распознаётся, голубой — всё распознано, можно отправлять сразу, зелёный на 1 с — отправлено, красный на 1 с — фраза сброшена словом «отмена», фиолетовый на 1 с — делается скриншот, серый — после удаления;
и окно с ответом Claude. Их положение задаёт `HUD` в `web/src/main.js`.
